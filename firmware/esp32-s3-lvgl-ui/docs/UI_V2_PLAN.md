# LVGL UI 重规划（v2 中文产线版）

> 依据：`~/cow/esp32-s3-lvgl-ui/` 现状代码实测（2026-10-01），非凭记忆。
> 需求来源：用户口述 —— 开机 Logo → 菜单 → 选语言 → 设时间 → 保存 → 出厂默认；
> 全部中文；按键物理不变；功能含 探针检测/烧录/DMC/DC/直通/故障诊断。

### 结论：三个硬缺口
1. **中文字体没编** —— 「全中文」当前 0% 可行
2. **四个功能模块没移植** —— dmc/dc/direct/fault 在固件里不存在，UI 画了也是空壳
3. **没有时间/配置持久化** —— 「设置后保存」当前无处可存

## 二、开机流程（Boot Flow）

```
上电
 └─ 0.0s  Logo 页（LOGO 2.0s，可用长按 BACK 跳过）
     └─ 读 NVS "ui_cfg"/"cfg_ver"
         ├─ 不存在 ─────► 首启向导：语言 → 时间 ─┐
         └─ 存在 ── 直接进主菜单 ───────────────┤
                                                 ▼
                                         写 NVS + 落盘确认
                                                 ▼
                                          主菜单（出厂默认态）
```

**「设置完之后就是出厂设置默认的」** 我的解读：向导走完 → 写入配置 → 进入**主菜单首页**（不是停在设置页），此后所有可调项处于默认值。**恢复出厂**是设置页里的一个独立动作。

## 三、主菜单 IA（3×3 九宫格，物理不变）

| | 列 1 | 列 2 | 列 3 |
|---|---|---|---|
| **行 1** | 🔍 探针检测 | ⬇ 烧录器 | 🔗 DMC 链路 |
| **行 2** | ⚡ DC 电源 | ↔ 直通控制 | 🩺 故障诊断 |
| **行 3** | ⚙ 系统设置 | 📊 状态信息 | ℹ 关于 |

6 个功能 + 设置 + 状态 + 关于 = 9 格，正好填满九宫格，**不改布局语法**（仍是 92×48 格 + 反色光标）。

**为什么「探针检测」独立于「烧录器」**：
检测 = *回答"探针那头接的是什么"*（被动、只读、零破坏）；
烧录 = *已知是什么之后动手*（擦/写，有破坏性）。
混在一起用户无法安全地"只想问一下"。

## 四、按键语义（物理不变，语义统一到三层）

| 按键 | 行为 |
|---|---|
| 短按 UP / DOWN | **在当前页内移动光标**（行间）——不再"翻页" |
| 长按 UP | 进入 / 执行光标项 |
| 长按 DOWN | 返回上一级（子页 → 功能页 → 主菜单） |
| 短按 BACK | 立即回主菜单（任何层级） |
| 长按 BACK | 开关 AUTO 轮播（保留现行为） |

**关键**：功能页沿用 **PROG 页已验证的架构** —— 每页提供 `xxx_page_key(id, is_long)`，按键**先交本页处理**，本页不消费才落回全局规则（`ui.c:1063-1065` 现状）。这样新页不破坏现有导航。

## 五、各功能页交互规格

### 1. 🔍 探针检测
| 行 | 内容 |
|---|---|
| 档案 | s3-spi / w25q / s3-isp（循环切换） |
| 驱动 | SIM（模拟）/ REAL（真机） |
| **开始检测** | 执行 |
| 结果 | 见下 |

**检测流程**：SPI `0x9F` 读 JEDEC → 译厂商+容量；UART `0x7F` 握手读 PID。
**诚实失败**：无应答 → 显示「未检出 · 查跳线/供电/档位」，**不显示假 ID**。

### 2. ⬇ 烧录器（现有 PROG 页扩展）
保留：`档案 / 驱动 / 镜像` + `READ ID / ERASE / PROGRAM / VERIFY / ISP SYNC`
新增：`读容量`（C7）、`整片擦除`（D8，带二次确认）

### 3. 🔗 DMC 链路
| 行 | 实时显示 |
|---|---|
| 从机地址 | 1..247 |
| 载荷长度 | 0..249（**上界硬约束**，UI 必须挡住） |
| 发送模式 | 广播 / 单播 |
| HELLO / DATA / STATUS / RESET | 按钮执行 |
| CRC16 自检 | 标准向量 `crc("123456789")=0x29B1` |
| **统计** | 帧 hex、rx/tx/err 计数、末次状态 |

### 4. ⚡ DC 电源
| 行 | 实时显示 |
|---|---|
| 侧别 | 输入 / 输出 |
| 信号 | 8 选 1：INPUT/OUTPUT/MAXIN/MININ/MAXOUT/MINOUT/HILITE/LOLITE |
| 设定值 / 窗口 / 参考预值 | 数值编辑 |
| 上电 OPEN / 断电 CLOSE | 会话门禁 |
| DCPP 帧自检 | 9 命令 + CKSUM8 校验 |
| **读数** | 采集值、窗口判决 PASS/FAIL |

### 5. ↔ 直通控制
| 行 | 说明 |
|---|---|
| 通道 | UART / I2C / PWM |
| 参数 | 波特率 / 地址 / 频率·占空 |
| 开关 | 启用/停止透传 |
| 吞吐 | 收发字节计数 + 回环校验 |

### 6. 🩺 故障诊断
| 行 | 说明 |
|---|---|
| 扫描 | 探针 10 脚逐脚判定 |
| 逐脚 | GND/RS/CS/SCL/SDA/RESET/VDD/GND/LED+/LED- |
| 注入故障 / 清除 | 验证诊断链路本身有效 |
| 汇总 | ok=2 / nolink=6 / bad=0 三态统计 |

### 7. ⚙ 系统设置
| 行 | 交互 |
|---|---|
| 语言 | 中文 / English（**默认中文**） |
| 年 / 月 / 日 | 上下调 |

## 六、配置持久化设计

```
NVS namespace: "ui_cfg"
  cfg_ver   u8    版本号，不存在 ⇒ 首启 ⇒ 走向导
  lang      u8    0=中文 1=English
  epoch     i64   设定时刻（掉电不丢，无 RTC 时靠它恢复）
  sntp      u8    0/1
  -- 恢复出厂 = nvs_erase_all("ui_cfg") + esp_restart() --
```

**无 RTC 的诚实说明**：时间存的是「设定那一刻的绝对时刻」，上电用 `NVS epoch + 运行时 tick` 推进。掉电期间不走时（无 RTC 无法做到），SNTP 开启且联网时可自动纠正。

## 七、字体方案（关键取舍）

| 方案 | 体积 | 评价 |
|---|---|---|
| 开 LVGL 全量 CJK 14+16 | **2.39MB** | 占 4MB 分区的 60%，挤掉后续模块空间 ❌ |
| **lv_font_conv 子集**（只含 UI 用到的 ~300 字） | **约 20-40KB** | **推荐** ✅ node v22.22.2 可用 |

步骤：把全部中文文案汇成清单 → `lv_font_conv` 生成子集 `.c` → 置 `lv_font_ui_zh_16` → 全文案走 i18n 表。

## 八、i18n 表结构

```c
typedef struct { const char *zh; const char *en; } str_t;
extern const str_t UI_STR[];          /* 唯一文案来源 */
extern uint8_t     g_lang;            /* 0=中文(默认) */
#define S(id)  (UI_STR[id].p[g_lang])  /* 用法: lv_label_set_text(l, S(SID_BURN)) */
```

好处：**中文是默认且唯一必填项**；加英文只是补一列，不改任何调用点。

## 九、实施阶段

| 阶段 | 内容 | 产出判据 |
|---|---|---|
| **P0** | 中文字体子集 + i18n 表 + NVS 配置层 | 中文能上屏；断电重启设置不丢 |
| **P1** | Logo 页 + 首启向导（语言→时间→保存） | 首启走完进主菜单，二次开机跳过 |
| **P2** | 主菜单 9 格重排 + 各页中文化 | 九宫格可导航，PROG 页不回归 |
| **P3** | 探针检测页（后端扩 `prog_api`） | REAL 模式能读出 JEDEC / 无芯片时诚实失败 |
| **P4** | dmc / dc / direct / fault 移植 + BSP + 4 页 | 4187 行移植，主机对拍 + 真机自证 |
| **P5** | 状态页 + 时间栏 + 整机回归 | 全页逐屏渲染自证 |

**P4 是最大工作量**（占 70%+），建议 P0-P3 先落地拿到可用产品，P4 分批做。

## 十、风险登记

| 风险 | 说明 | 缓解 |
|---|---|---|
| P4 移植量 | 4187 行 xiaomo 代码需适配 S3 + 各自 BSP | 逐模块移植，每模块沿用 PROG 的「worker + 快照」线程模型 |
| 脚位复用 | DMC 半双工 SPI、DC 采样、故障扫描都想要探针脚 | 探针脚互斥，UI 设页显示占用状态 |
| Flash | 字体若走全量会挤爆分区 | 强制子集字体，CI 校验体积 |
| 无 RTC | 掉电不走时 | SNTP 兜底 + 文档明说 |
| 破坏性操作 | 整片擦除/烧录可能误触 | 二次确认 + REAL 模式默认不写 |
