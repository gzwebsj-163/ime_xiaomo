## 一、判读的前置闸（不满足则后面全部作废）

| 闸 | 判据 | 不满足时的处置 |
|---|---|---|
| **G0 产物身份** | `rst:0x` 恰好 1 次；崩溃关键字全 0 | 判「实验环境不可信」，不出结论 |
| **G1 运行模式** | 日志含 `A(IOMUX)`/`B(matrix)` 行；**不含** `isolated honest-fail` | 若出现 Phase C 行 → 刷错固件，**作废重来** |
| **G2 [AB0] 采样法自证** | 驱动低读到低 ≥190/200 **且** 驱动高读到高 ≥190/200 | **直接判「本轮无结论」**（verdict=-1），不是判 matrix 不通 |
| **G2b [AB-G] 路由闸**（r2 新增，r3 修正措辞） | A 臂 `MCU_SEL=4` **且** `func_sel=256`；B 臂 `MCU_SEL=0` **且** `func_sel=101`。**口径**：这两个值分出 `IO_MUX` 与 `FUNCx_OUT_SEL_CFG` **两个不同寄存器**，故 G2b 相对 pad 电平确为独立通道；但 `func_sel=` 字段本身**不是**独立口径（见 §七·2） | 该臂**数据不可用**。此时「读到 0」归因于驱动没布路由，**不得归因于 matrix 不通** |
| **G3 空闲基线** | A/B 两臂发送前基线均 `低电平=500/500` | 基线非全低 → 该臂被外部占用，作废该臂 |

> G2 的意义：UART 那次的 `CX1`/`CX2` 共享「pad 能否读回内部驱动信号」的盲点。
> G2 就是拆这把刀。**G2 不过时，「读到 0」与「根本没驱动」同值，不可解读。**
>
> G2b 的意义：拆**另一半**盲点「路由根本没建」。寄存器读数与 pad 读数走**不同硬件路径**，
> 前者是仪器事实、后者是波形事实。G2 证「采样法是活的」，G2b 证「路由按预期机制建起来了」，
> 二者同时过，「B 臂读到 0」才第一次具备可归因性。

## 二、裁决矩阵

| [AB1] A 臂高电平 | [AB2] B 臂高电平 | verdict | 结论 |
|---|---|---|---|
| > 0 | > 0 | **1** | **SPI matrix 出向通** —— FSPI 可路由到任意 GPIO（与 UART 侧不同！） |
| > 0 | = 0 **且 G2b(B臂) 通过** | **2** | **SPI matrix 出向不通** —— 寄存器已独立证实路由确实建立，仍无波形。与 UART 侧一致，第一刀必须用 IOMUX 专属脚 |
| > 0 | = 0 **且 G2b(B臂) 不通过** | **-1** | **无效** —— 路由压根没按预期机制建，读 0 不可归因于 matrix 不通 |
| = 0 | 任意 | **-1** | **无效** —— 阳性对照失效，**不得据此说 matrix 不通** |
| < 0（臂启动失败） | 任意 | **-1** | **结构性失败，查 rc |

> 最后三行是本判据表的核心价值：**没有波形时，唯一诚实的结论常常是「无效」。**
> 这正是 UART 那次「读不回产生完全相同读数」的盲点所在。
> r2 追加的第二行尤其重要：它把 verdict=2（对外可用的强结论）的门槛
> 从「A 臂有波形 + B 臂没波形」抬高到「**还要寄存器证实 B 臂路由已建**」。

## 三、已知的替代解释（逐条排除，不得跳过）

即使 G2/G2b 全过、B 臂读到 0，仍**不能**直接判「matrix 不通」，除非排除：

| # | 替代解释 | 排除方法 | 状态 |
|---|---|---|---|
| 1 | B 臂引脚被别的外设占用 | 逐一核对 B 组（4/5/6/7）不在 PSRAM(33~37)/strapping(0/3/45/46)/USB-JTAG(19/20)/UART0(43/44) | ✅ 代码注释已固化 |
| 2 | B 臂传输根本没启动（任务没跑） | 查 `spi_bus_initialize` / `add_device` 的 rc 是否 0 | ⬜ 需读日志 |
| 3 | 采样窗口没覆盖传输 | 传输在后台任务连发 40 次 × 64B，主循环采 7000 点 | ✅ 设计已覆盖 |
| 4 | ~~脚被内部下拉钉住读不到高~~ | **r2 已消除**：删掉 `GPIO_PULLDOWN_ENABLE`，改用只置 `FUN_IE` 的 `PIN_INPUT_ENABLE`（`io_mux_reg.h: FUN_IE=BIT(9)` 与 `MCU_SEL=bits12-14` 不相交） | ✅ 结构性消除 |
| 5 | **矩阵路由建了但 pad 读不回** | G2b 只能证「`func_sel=101` 已写入」，**不能**证 pad 输入缓冲器能读回经矩阵驱动的信号 | 🔴 **残余风险，见下** |

> 🔴 **替代解释 5 是本实验唯一的残余风险，r2 无法消除它。**
> 上一轮 UART 的 `[CX1]`/`[CX2]` 就是死在这里：「发送中连采 pad」与「对端计数」
> 共享「pad 输入缓冲器能否读回内部驱动信号」这个盲点，**该结论现已不可独立复核**
> （10-02 跑批日志从未归档 + 板子已被覆盖），只能当单源记载。
>
> G2（`[AB0]`）证的是「**纯 GPIO 内部驱动**能读回」；它**没有**证
> 「**经 GPIO Matrix 外设路由**驱动的信号能读回」——这在硅层面是否等价，源码查不到
> （`esp_rom_gpio_connect_out_signal` 是 ROM 函数，IDF 仓库无实现体）。
>
> **若本轮判 verdict=2（matrix 不通），必须同时写明这条残余风险仍开放。**
> 要彻底闭合需要**示波器**或**物理跳线**（引脚短接到一个已知能被读回的脚），
> 本轮不具备条件，不得假装已排除。

## 七、判据表自身是怎么被验过的（r3 新增）

> 起因：板子未插、取不到数据。而「判据表 + 判读器」本身是**未经验证的工具**。
> 未验证的工具做出的裁决，和没有裁决一样不可信 —— 甚至更危险，因为它看起来严谨。
> 故在取数据前先把**裁判本身**验一遍。

### 1. 固件自带裁判，且漏实现两道闸 ⇒ 外部判读器是必需品

`pin_spi_ab.c:453-478` 已有裁决逻辑，经逐条核对**与本表裁决矩阵等价**。但：

| 闸 | 固件 | 后果 |
|---|---|---|
| G2 采样法自证 | ✅ `:419-424` | 符合 |
| **G0 `rst:0x` 恰好 1 次** | ❌ **物理上无法自检** | 崩溃-重启循环的跑批会被当有效数据，固件照常裁决 |
| **G3 空闲基线 500/500** | ❌ **采了但不用** `:364-372` 只打印，`:453-478` 完全未引用 | 该脚被外部拉高时固件仍会给出不可信的 verdict=1/2 |

⇒ 新增 `judge_spiab.py` 作为**独立第二实现**，补这两洞，并与固件 verdict **交叉比对**
（不一致时显式报警，不静默取其一）。

### 2. 撤回一处不成立的「独立口径」

曾把「自行从 `FUNCx_OUT_SEL=0x…` 低 9 位重算 `func_sel`」写成锚点 A 独立口径。
**源码 `pin_spi_ab.c:244-245` 推翻它**：

```c
r->out_sel_raw  = REG_READ(GPIO_FUNC0_OUT_SEL_CFG_REG + ck * 4);
r->out_func_sel = r->out_sel_raw & 0x1FFu;   // 恒等
```

⇒ 固件打印的 `func_sel=` **恒等于**原始寄存器低 9 位，该对拍在**真实硬件上永不触发**，
只可能被伪造日志触发 = **死代码**。它仅剩的价值：若两字段对不上，说明**日志被截断/串行化错位/解析失配**。

**削弱的是**「func_sel 有两个独立口径」这句话 —— 撤回。

### 6. 第四种形态：检索口径错误造成的「假缺失」（r4 新增）

核实回烧三段时，我执行 `ls build_v3/*.bin` 判定「bootloader 与分区表 **MISSING**」，

- 错在哪：glob 只查顶层，把「我的查询没覆盖到」当成了「东西不存在」，
  然后**在这个错误结论上继续推理**（差点连带怀疑整个收尾流程）。
- 与既有坑的同构性：和「`grep` 零命中 ⇒ 常量已废弃」、「`head` 截断 ⇒ 校验工具坏了」
  完全同形 —— **都是关于检索方式的陈述，被当成了关于世界的陈述**。
- 纪律（补进锚点 F）：
  1. 「查不到」必须**换一种检索方式复验**（本例：递归 `find` + 显式子路径）后才准下结论；
  2. 一旦某个「发现」要推翻既有铁律或引发大动作（如判定收尾流程不可行），
     **先花十秒换个口径复验**，成本极低、误判代价极高。
